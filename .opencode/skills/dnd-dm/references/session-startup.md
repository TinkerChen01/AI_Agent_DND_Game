# 会话启动详细流程

> 补充 `dnd-dm` SKILL.md §三 会话启动。每次新对话/新会话开始时读取本文件。

---

## 1. 读取顺序

按以下顺序依次加载数据文件，**不得跳步、不得并行**：

```
1. 读取 L6 冒险笔记 → 叙事摘要（快速定位"我是谁"）
2. 读取 L6 → 前情提要（恢复叙事流与角色互动纹理）
3. 读取 L6 → 存档快照（获取定格画面，从此直接接续）
4. 读取 L6 → 最近 2-3 个节点（获取精确事件数据）
5. 读取 L1 世界设定 → 锚定世界观基调
6. 读取 L2 模组框架 → 了解当前剧本节点
7. 读取 L4 + L5 → 获取精确数值和 flag
8. 角色 Skill（dnd-kafka / dnd-lance）会在对话中自动触发加载，无需手动读取
9. 城市休整时使用 dnd-city-rest Skill（无需手动读取原 L7 文件）
```

## 4. ⚠ 会话启动陷阱（必读）

**必须在完成全部数据读取（§1）之后再开始任何叙事，尤其是 L2 模组框架。**

### 常见翻车场景

**场景一：未读 L2 就开始叙事**
玩家从 L6 存档快照接续后直接行动（如"我踹开地窖门"）→ 但你还没读 L2 → 不清楚门后有魔法封印/人偶/谜题 → 结果编出来的内容与模组设计矛盾。

**场景二：角色 Skill 未触发就扮演角色**
提到卡芙卡或兰斯时，如果对应的角色 Skill（dnd-kafka / dnd-lance）尚未自动加载 → 角色性格可能写走样。通常 Skill 会根据关键词自动触发，如发现角色扮演质量下降，可手动加载对应 Skill。

**场景三：未读 L4 就进行检定**
需要进行检定 → 但你还没读 L4 → 不知道角色当前属性/HP/可用资源。

### 正确做法

记住读取顺序之后，**显式地依次读取**（L6 → L1 → L2 → L4+L5），确认都到位了再开口叙事。

玩家催得急也不要跳步——信息不完整时宁可说"我先确认一下"再读文件。
