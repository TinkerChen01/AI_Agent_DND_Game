# D&D 新模组生成

## 一、触发条件

- **dnd-settle 结算完成后**，步骤"确认新起点"时自动建议生成新模组
- 玩家主动说"新模组"/"生成模组"/"下一个冒险"
- DM 判断当前模组已结束且玩家需要新内容

## 二、前置准备

1. 读取 **L4（角色状态）** → 确认队伍等级、装备、关系
2. 读取 **L5（世界状态）** → 确认当前位置、势力动态
3. 读取 **L6 过往冒险摘要** → 确认已有剧情，避免重复
4. 读取 **`dnd-dm/references/causal-chain.md`** → 确认待兑现的伏笔，选择可在新模组中回收的线索
5. 确认素材库路径：`AI跑团模组素材库（只有创作新模组时才读取，其他情况禁止读取）.md`

> **与 dnd-expand 的边界**：本 Skill 用于创建完整的新模组（新地区/新故事/新 NPC 阵容）。如果只是在当前模组地图内补充 1-3 个空白场景，应使用 dnd-expand。详见 dnd-expand SKILL.md 的边界判断表。

## 三、素材抽取流程

1. 根据队伍等级确定可用素材池（初级 / 中级 / 高级）
2. 读取素材库的**任务类（§二）** → 抽取核心冲突
3. 根据核心冲突类型，抽取匹配的**怪物（§一）**和**宝物（§三）**
4. 检查 **L1 世界观兼容性**（不违反 Forgotten Realms 设定）
5. 检查 **L6 历史兼容性**（不复用已解决的事件 / NPC）
6. 记录所有素材编号

## 四、模组生成流程

1. 执行骨架生成脚本：
   ```bash
   python scripts/generate_skeleton.py --name "模组名" --level "Lv.X→Lv.Y" --regions N
   ```
2. 读取生成的骨架文件
3. 按模板填充内容，参考 `references/module-template.md` 和 `references/design-guide.md`
4. 每个地区必须包含：**空间布局 ASCII 图** + **floorplan JSON**
5. 每个节点必须包含：**场景描写（≥200字）** + **互动要素表** + **可搜索物品表**
6. 关键战斗场景必须提供预制 **combat JSON**
7. 填充 **§〇 速查索引**（确保与正文一致）
8. 填充 **§七 失败安全网** + **§八 完成条件**

## 五、质量验证

1. 执行验证脚本：
   ```bash
   python scripts/validate_module.py
   ```
2. 检查项：§〇 完整性、节点连续性、地图数据存在性、必填字段无遗漏
3. 若有报错，修复后重新验证
4. 验证通过后，将 L2 文件写入项目根目录

## 六、初始化游戏状态

1. 读取 L2 **§八** 的"L5 初始状态模板"
2. 用模板数据初始化 **L5**（清除旧模组的任务 / flag，填入新的）
3. 重置 **L6**（保留过往冒险摘要，清空节点和会话索引）
4. 更新 **L4 关系表**（保留跨模组关系）

## 七、与其他 Skill 的集成

| Skill | 集成方式 |
|---|---|
| **dnd-settle** | 结算完成后调用本 Skill 生成新模组 |
| **dnd-map** | 读取 L2 §〇 索引表定位地区，读取 §二 floorplan JSON 渲染地图 |
| **dnd-expand** | 扩展空白区域时必须遵循模板的节点格式 |
| **dnd-dm** | 会话启动时只读 L2 §〇 定位内容，不全文读取 |

## 八、注意事项

- 素材库文件**仅在生成新模组时读取**，日常游戏中绝对禁止读取（节省 token）
- 每个模组最多 **2 个地区、8 个节点、5 场战斗**（含 Boss）
- 生成的模组必须通过 `validate_module.py` 验证才能使用
- ASCII 空间布局图必须与 floorplan JSON 一致
- 失败安全网必须覆盖至少 **5 种场景**
