# 模组设计指南 v1.0

> 补充 module-template.md 之外的设计原则与方法论。
> 生成新模组时，AI 应先读完本指南再开始填充模板。

---

## 一、难度校准

### 1.1 等级与 CR 匹配

| 队伍等级 | 适合敌人池 | Boss CR 建议 | 战斗场次 | 预期资源消耗 |
|---------|-----------|-------------|---------|------------|
| Lv.1-3 | 初级（P/PH） | CR 2-3 | 2-3 场 | 中等（2-3 瓶药水） |
| Lv.4-6 | 初级+中级混搭 | CR 4-6 | 3-4 场 | 较高（3-5 瓶药水+法术位） |
| Lv.7-9 | 中级+少量高级 | CR 7-9 | 3-5 场 | 高（需要长休规划） |
| Lv.10+ | 中级+高级 | CR 10+ | 4-5 场 | 极高（需要战术配合） |

### 1.2 混搭原则

- 一个中级怪 ≈ 三到五个初级怪（数量代替质量）
- Boss 战应有至少一个"非蛮力解法"（说服/破坏环境/机制破解）
- 可选战斗不算入预期资源消耗

### 1.3 短团 vs 中团

- **短团（1 章）**：1 个地区，3-5 个节点，1 场 Boss + 1-2 场普通战
- **中团（2-3 章）**：2 个地区，5-8 个节点，1 场 Boss + 2-4 场普通战

## 二、素材抽取规则

### 2.1 从素材库抽取

素材库路径：`AI跑团模组素材库（只有创作新模组时才读取，其他情况禁止读取）.md`

**抽取步骤：**

1. 确认队伍等级 → 确定可用池（初级/中级/高级）
2. 确定故事引擎类型 → 从对应任务类型中抽取核心冲突
3. 按地区类型抽取怪物（地下→洞穴类/森林→自然类/城镇→人形类）
4. 按节点需要抽取宝物（Boss 掉落用稀有池，搜索发现用稀有池低档）
5. 记录所有抽取编号 → 填入 §一 素材引用

### 2.2 兼容性检查

抽取素材后，必须检查：

| 检查项 | 方法 |
|--------|------|
| L1 世界观兼容 | 素材不违反 Forgotten Realms 基础设定 |
| L6 历史兼容 | 不复用已死亡/已解决的 NPC 或事件 |
| 前模组伏笔衔接 | 若前模组留有钩子，优先考虑与之关联的素材 |
| 角色能力匹配 | 不设计只有特定职业/种族才能通过的硬性门槛 |

## 三、地区设计方法

### 3.1 空间结构

每个地区必须有明确的**物理边界**和**内部结构**：

- **室内型**（庄园/城堡/神殿）：房间 + 走廊 + 楼梯，需要楼层图
- **野外型**（森林/山脉/沼泽）：路径 + 节点 + 自然障碍，需要区域图
- **城镇型**（村庄/城区）：建筑 + 街道 + NPC 分布，需要街区图
- **地下型**（地下城/矿洞）：房间 + 通道 + 岔路，需要地图
- **异空间型**（画中世界/梦境）：场景碎片 + 连接规则，需要关系图

### 3.2 节点密度

- 每个地区 3-5 个节点（含开场和 Boss）
- 每个节点至少包含：场景描写（200+ 字）+ 互动要素表 + 可搜索物品表
- 节点之间应有**至少一条不需要战斗的路径**

### 3.3 两地区衔接

当模组有 2 个地区时，衔接方式建议：

| 衔接类型 | 示例 | 适用场景 |
|---------|------|---------|
| 地理递进 | 村庄→村庄外的遗迹 | 探索型 |
| 信息驱动 | 在 A 地获得线索→前往 B 地 | 解咒型/讨伐型 |
| 被迫转移 | A 地被毁/被占→逃往 B 地 | 防卫型 |
| 时间跳跃 | A 地事件→数日后→B 地事件 | 任何类型 |

## 四、场景氛围生成规则

### 4.1 五感描写清单

每个节点的场景描写必须覆盖至少 **3 种感官**：

| 感官 | 室内常见 | 野外常见 | 地下常见 | 异空间常见 |
|------|---------|---------|---------|-----------|
| 视觉 | 光照/装饰/灰尘 | 天空/植被/地形 | 黑暗/矿物/壁画 | 色彩失真/空间扭曲 |
| 听觉 | 回声/机械声/寂静 | 风声/虫鸣/水声 | 滴水/远处轰鸣 | 不自然的静默 |
| 嗅觉 | 霉味/蜡烛/食物 | 泥土/花香/腐臭 | 铁锈/硫磺/潮湿 | 油彩/甜腻/金属 |
| 触觉 | 温度/湿度/材质 | 风/地面/阳光 | 寒冷/潮湿/粗糙 | 失真/漂浮感 |
| 第六感 | 被注视感/不安 | 方向迷失 | 压迫感 | 时间感消失 |

### 4.2 环境叙事碎片

每个地区至少包含 **3 个环境叙事要素**——不通过 NPC 对话而是通过环境本身讲述故事：

- 物品摆放的异常（如：餐桌上摆了三套餐具但只有一个人住）
- 时间的痕迹（如：蜡烛烧不完/时钟停在某个时刻）
- 人为干预的痕迹（如：画框被刮花/门被从里面钉死）
- 自然反常（如：花园里只有一种花在开/所有鸟都不叫了）

## 五、环境机关与陷阱设计

### 5.1 设计原则

- 机关必须**可被发现**（DC 不超过队伍平均感知调整值 + 10）
- 机关必须**有叙事功能**（推进剧情或揭示背景，不是纯粹障碍）
- Boss 房的机关应该是**双刃剑**（对玩家和 Boss 都有效）

### 5.2 机关类型

| 类型 | 示例 | 适用场景 |
|------|------|---------|
| 锁/封印 | 魔法封印石门/密码锁/钥匙锁 | 区域入口 |
| 陷阱 | 压力板飞箭/毒气喷口/坍塌地板 | 通道/房间 |
| 环境危害 | 不灭火焰/酸液池/活化植物 | 战斗场地 |
| 信息机关 | 需要特定物品触发/对话触发/时间触发 | 解谜节点 |
| 防御机制 | 被攻击才激活的守卫/入侵检测 | 禁区 |

## 六、失败安全网设计方法

### 6.1 必须覆盖的失败场景

| 场景 | 设计要点 |
|------|---------|
| 关键 NPC 死亡 | 准备"死前信息传递"（日记/遗言/第三人转述） |
| 关键线索遗漏 | 每条关键线索至少 2 个获取途径 |
| Boss 被蛮力击杀 | 准备"暴力结局"的叙事后果（通常比最佳结局差） |
| 玩家拒绝任务 | 准备补位钩子（悬赏/偶遇/被迫卷入） |
| 玩家跳过地区 | 核心信息可通过替代方式获得（NPC 转述/远处观察） |

### 6.2 兜底不等于惩罚

失败安全网的目标是**让故事继续**，不是惩罚玩家的选择。
差的兜底：NPC 死了，线索全断，模组无法继续。
好的兜底：NPC 死了，但从他身上掉出一封未寄出的信，关键信息仍然到手——只是玩家错过了 NPC 的个人故事线。

## 七、ASCII 地图预制规范

### 7.1 地区空间布局图

用 ASCII 绘制的空间布局图应包含：
- 所有房间/区域及其相对位置
- 通道/楼梯/门的位置和状态（开放/上锁/封印）
- 楼层标注（3F/2F/1F/B1 等）
- 关键物品/NPC 的大致位置标注

### 7.2 floorplan JSON

每个地区必须提供一个 floorplan JSON，格式参见 `dnd-map` SKILL.md。
关键字段：`title`、`floors`（含 `id`/`name`/`status`/`rooms`）、`connections`。

### 7.3 combat JSON

每场预设战斗必须提供一个初始 combat JSON，包含：
- 预设地形（墙壁/家具/自然障碍）
- 初始实体位置（玩家起始位 + 敌人起始位）
- 图例说明

AI 在战斗触发时直接读取此 JSON 调用 `render_map.py`，无需从零构造。

## 八、质量检查清单

模组完成后（或生成后），用以下清单做最终检查：

- [ ] §〇 所有表格完整且与正文一致
- [ ] 每个节点都有场景描写（≥200 字）+ 互动要素表 + 可搜索物品表
- [ ] 每个地区都有 ASCII 空间布局图 + floorplan JSON
- [ ] 每场战斗都有敌人数据表 + 环境描写 + 胜利条件
- [ ] 失败安全网覆盖所有"必选"场景
- [ ] 完成检查清单的条件可被明确验证
- [ ] 素材编号与素材库匹配
- [ ] 无术语混用（同一事物只用一个名称）
- [ ] 难度校准表合理（CR/战斗数/资源消耗）
- [ ] L5 初始状态模板完整
