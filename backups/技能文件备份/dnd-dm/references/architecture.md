# Skill 架构说明

> 本文档记录 `dnd-dm` 技能体系的架构设计原则，面向后续调用此技能的 AI 或修改此体系的开发者。

## 核心原则：职责分离

本体系采用**主 Skill + 子 Skill** 两层架构，以 system prompt 效率为优先考量：

### dnd-dm（主 Skill）— 注入 system prompt，全程有效

- 定义 **WHEN（什么时候做什么事）**
- 包含：模式切换、会话启动规则、叙事原则、战斗规则（非流程）、关系判定逻辑、数据同步条件、DM 红线、主线归位原则
- 不包含详细的操作步骤——那些在子 Skill 里
- 用户的工作偏好（如节奏控制、确认规则）也放在这里，因为这是跨 session 的行为规范

### dnd-*（子 Skill）— 按需加载，聚焦 HOW

- 定义 **HOW（具体怎么做）**
- 每个子 Skill 是自完备的——不依赖主 Skill 提供操作细节
- 直接引用项目文件（L4_角色状态.md、L5_世界状态.md 等），不引用 L0 或其它已不存在的文件
- 适用场景：存档、战斗初始化、节点追加、模组扩展

### 为什么这样设计

1. **system prompt 空间有限**。dnd-dm 注入后全程占用 token。如果把全部子流程细节都塞进来（节点格式、存档 checklist、L4b 写入规范），每轮对话浪费数百 token。
2. **需要时才加载**。战斗流程只在战斗前需要；存档流程只在玩家说"存档"时需要。这些操作细节不必常驻 system prompt。
3. **子 Skill 作为"操作手册"**。当 AI 遇到相应场景（战斗开始、玩家要求存档），去读取子 Skill 的详细操作指引即可，dnd-dm 里的规则仍然保障 AI 不会跑偏。

## 文件引用规则

1. **dnd-dm** 引用子 Skill 时使用「详见 `dnd-存档` Skill」的形式
2. **子 Skill** 引用项目数据文件时使用相对路径（相对于项目目录），如 `L4_角色状态.md`
3. **子 Skill** 不反向引用 dnd-dm 的操作细节——子 Skill 是自完备的
4. 项目文件中原本指向 `L0` 的引用，已在迁移过程中改为指向 `dnd-dm` Skill

## 技能体系总览

```
dnd-dm（主 Skill）
├── 模式切换 / 会话启动
├── 叙事原则 / NPC 扮演
├── 战斗规则 vs 战斗流程（流程指向子 Skill）
├── 数据同步条件（条件在 dnd-dm，格式在子 Skill）
├── 关系判定 / 回滚协议 / 红线
├── 工作规范（用户偏好）
│
└── 子 Skill：
    ├── dnd-存档     → 完整存档步骤
    ├── dnd-战斗开始  → 战斗初始化步骤
    ├── dnd-查询     → 情报检索步骤
    ├── dnd-检查点   → 轻量状态同步步骤
    ├── dnd-模组扩展  → 模组动态扩展步骤
    └── dnd-节点     → 节点追加步骤
```
