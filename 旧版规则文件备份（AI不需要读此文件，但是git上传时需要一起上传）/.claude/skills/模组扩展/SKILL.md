# 模组扩展

玩家主动触发的元指令技能。当玩家感觉到当前方向模组没有覆盖时，申请 AI 检测空缺并动态扩展模组内容，扩展结果写回 L2 体系，保证跨会话一致。

**核心原则**：仅扩展空白，不覆盖已有，不剧透，不替玩家做决定。

---

## 触发规则

### 谁触发

**玩家主动触发。** AI 不得自触发——即使检测到空缺也等玩家指令。

### 如何触发

玩家使用自然语言即可，例如：
- "扩展一下竞技场"
- "这个地下室模组有写吗？帮我补一下"
- "我想去接个支线任务，这里模组有设计吗"
- "帮我扩展一下这个方向"

### 触发时机

玩家感受到以下任意情形时：
- 想去一个模组未预见的场景（如竞技场、拍卖行、港口）
- 想探索一个模组未定义细节的空间（如某扇门后、地下室结构）
- 想做当前模组未设计的支线任务
- 其他任何感觉"这里模组可能没写"的时刻

### 触发语气

使用**元指令语气**（不是游戏内角色对话），与游戏叙事分离。

✅ 正确：*"帮我扩展一下竞技场"*
❌ 错误：*兰斯说："我想去竞技场看看，这里有什么？"*（这是游戏内行动，不是扩展指令）

## 执行流程

```
玩家指令
  │
  ▼
读取 L2_模组框架.md → 定位玩家所指区域
  │
  ├─ L2 已有覆盖 → 汇报 🔍 模组已覆盖，无需操作
  │
  └─ L2 确实空缺 → 读取以下文件锚定上下文：
  │     ├─ L1_世界设定.md（世界观一致性）
  │     ├─ L2_模组框架.md（相邻节点风格/难度/基调）
  │     ├─ L5_世界状态.md（当前 flags / 时间 / 场景）
  │     └─ L6_冒险笔记.md（已发生事件/已知情报）
  │     │
  │     └─ 执行扩展写入：
  │           ├─ 写入 L2 对应章节（优先）
  │           ├─ 或另建 L2b_副文件（内容较多时）
  │           ├─ 追加一个或多个 L1 条目（如新增世界观设定）
  │           │
  │           └─ 更新 L6 节点记录（type: 模组扩展）
  │           └─ 汇报 📝 模组已扩展
  │
  ▼
等待玩家回到游戏叙事
```

### 文件写入策略

| 内容量 | 写入位置 | 示例 |
|--------|---------|------|
| 单个场景/区块（< 50 行） | 追加到 L2 对应章节 | L2 追加「竞技场」小节 |
| 完整支线/大型区域（≥ 50 行） | 新建 `L2b_区域名.md` | L2b_竞技大会.md |
| 新增 NPC/地点/组织 | 追加到 `L3b_重要NPC档案.md` 或 L1 对应章节 | — |

### 跨会话说明

扩展内容写入 L2 体系后，下次会话启动协议读取 L2 时自动加载，无需额外操作。L6 的节点记录确保我能追溯到"何时为何做了扩展"。

---

## 汇报格式

汇报使用固定格式，不涉及内容细节、不剧透。

### 模组已覆盖

> **🔍 模组已覆盖**：这个方向已有现成设计，无需扩展，直接继续即可。

### 模组已扩展

> **📝 模组已扩展**：已补充相关框架，保持了一致性，可以继续。

两种汇报均不带叙事语气、不扮演任何角色、不暗示玩家"该做什么"。

---

## 扩展内容约束

1. **风格一致** — 氛围、难度、基调必须与 L2 邻近节点匹配
2. **世界观一致** — 不与 L1_Forgotten Realms 设定矛盾
3. **不绕过剧情锁** — 扩展不能提供捷径跳过已有的谜题/障碍/封锁区域。例如：不在庄园外墙上扩展一扇后门跳过大门谜题
4. **与主线有软连接** — 扩展内容尽可能为未来与主线交汇埋下伏笔，但不强制玩家走那条线。例如：竞技大会的获胜奖励中有一件物品恰好与主线线索相关
5. **不预设玩家行为** — 扩展内容仅提供"存在什么"，不制造"你必须去"的压力
6. **不剧透 L2 已有设计** — 即使检测到已覆盖，也不透露具体内容

## 典型案例

### 案例 A — 场景级扩展：未预见的去处

**背景**：主线是去神殿做任务，玩家突然说想去竞技场看看。L2 未设计竞技场。

**玩家触发**：
> *"帮我扩展一下无冬城的竞技场。"*

**执行**：
1. 读取 L2 → 确认无竞技场内容
2. 读取 L1（无冬城设定）+ L5（当前时间/氛围）
3. 在 L2 追加「⚔ 竞技场」章节，包含：
   - 场景描述（沙地、看台、旗帜）
   - 当前正在进行一场竞技大会（NPC 参赛小队）
   - 可能的互动路线：参赛、观战、接悬赏
   - 其中一支佣兵队的队长恰好对主线区域有所了解（软连接）

**汇报**：
> **📝 模组已扩展**：已补充相关框架，保持了一致性，可以继续。

---

### 案例 B — 建筑级扩展：未定义的空间细节

**背景**：玩家在庄园地下室问"这里通向哪儿"。L2 只写了"地下室有怪物"，未定义通道结构。

**玩家触发**：
> *"这地下室模组没细写吧？帮我扩展一下结构。"*

**执行**：
1. 读取 L2 → 确认地下室仅写了怪物遭遇
2. 读取 L5（庄园当前状态）+ L6（已有情报）
3. 在 L2 地下室部分补充拓扑结构：
   - 主室（已有怪物）+ 三条岔路
   - 左路：废弃酿酒窖（氛围填充）
   - 右路：走私密道（可通往庄园外）
   - 中路：坍塌的楼梯（可清理，通向……与主线交汇点）

**汇报**：
> **📝 模组已扩展**：已补充相关框架，保持了一致性，可以继续。

---

### 案例 C — 任务级扩展：未设计的支线

**背景**：玩家想把主线放一放，去酒馆接个活。模组只有一条主线，无支线任务表。

**玩家触发**：
> *"模组有支线任务设计吗？没有的话帮我扩展几个。"*

**执行**：
1. 读取 L2 → 确认无支线任务设计
2. 读取 L1（区域文化）+ L5（当前场景）+ L6（玩家近期行为）
3. 在 L2 追加「📜 支线任务」章节，包含：
   - 任务 A：清剿狼人（战斗向，奖励金钱+主线情报线索）
   - 任务 B：失踪商队调查（探索向，奖励装备+区域地图）
   - 任务 C：某富商的护卫委托（社交向，奖励关系+未来援军）
4. 每个任务均设计 1-2 个与主线的软连接点（情报/物品/地名）

**汇报**：
> **📝 模组已扩展**：已补充相关框架，保持了一致性，可以继续。

## 红线

- ❌ **不扩展已覆盖区域** — 检测到 L2 已有设计时，不动
- ❌ **不剧透** — 汇报不涉及内容细节。扩展内容自身也不暴露"原本没有"的痕迹
- ❌ **不替玩家做决定** — 扩展内容仅提供"存在什么"，不制造"你必须去"的压力
- ❌ **不绕过剧情锁** — 扩展不能捷径化、不能解构已有谜题设计
- ❌ **不改变主线走向** — 扩展以支线/细节/场景填充为主，不修改 L2 定义的核心剧情节点和解锁条件
